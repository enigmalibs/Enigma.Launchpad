# FEATURE-E90D — Windows MSI build script

**Status:** TODO

## Objective

One command builds the Windows installer: `packaging/windows/buildmsi.ps1` (and a `buildmsi.bat` twin) cleans the
repository, publishes the release, and builds `artifacts/Enigma.Launchpad.X.Y.Z.msi` with Enigma.Msi. The
repository carries a copy of Enigma.Msi's worker CLI. Exactly as Enigma.GitClient does it (its FEATURE-EAB7), with
the product named "Enigma Launchpad", its own upgrade code and its own version.

## Context & constraints

- **The model to follow** is Enigma.GitClient's FEATURE-EAB7 (`develop` @ `a58d8fe`):
  `packaging/windows/Enigma.Msi.Worker/` (20 binaries + `README.md`), `packaging/windows/buildmsi.ps1`,
  `packaging/windows/buildmsi.bat`, a `.gitignore` entry for `.wixsharp/`, tests pinning the identity, and the
  README / `docs/RELEASE.md` sections.
- **The installed product.** This machine has *Enigma Launchpad 1.4.0* installed from an MSI built with Enigma.Msi
  (its cached package read through the Windows Installer API, read-only, while planning):
  - `UpgradeCode` `{B4C2D5A2-9182-4C17-B570-C6019EB5EC92}`;
  - `ProductName` "Enigma Launchpad", `Manufacturer` "Josué Clément", `ALLUSERS` 1 (per machine);
  - `INSTALLDIR` = `ProgramFilesFolder\Enigma Launchpad`;
  - shortcuts "Enigma Launchpad" in `DesktopFolder` and `ProgramMenuFolder`, target
    `[INSTALLDIR]\Enigma.Launchpad.Desktop.exe`, icon `app.ico`; `ARPPRODUCTICON` set;
  - a compressed cabinet (`#Enigma20Launchpad.cab`).
  The new script must keep that upgrade code, Launchpad's own (GitClient's is another). A new one would install
  1.5.0 beside 1.4.0 instead of upgrading it.
- **Enigma.Msi** (`C:\Dev\EnigmaLibs\Enigma.Msi`, tag `1.7.0` = `a7a1bfb`, clean tree): its
  `src/Enigma.Msi.Worker/bin/Release/net472/` output is byte for byte GitClient's vendored copy (the `.exe.config`
  differs only in line endings). The CLI: `Enigma.Msi.Worker.exe build <file.msipkg.json>`; exit codes `0` built,
  `1` invalid package or failed build, `2` bad invocation. Needs the WiX CLI (`wix` 7.0.0 is installed here).
- **Publish** (FEATURE-B7DD): `packaging/windows/publish.ps1` runs `dotnet publish src\Enigma.Launchpad.Desktop -c
  Release -r win-x64 -p:PublishReadyToRun=true` and exits with dotnet's code. Result:
  `src\Enigma.Launchpad.Desktop\bin\Release\net10.0\win-x64\publish\`, with `app.ico` beside
  `Enigma.Launchpad.Desktop.exe` (FEATURE-7F4A).
- **The version** lives in `Directory.Build.props` (`<Version>`), and that file is UTF-8 (`Josué` in `<Authors>`).
- `.gitignore` ignores `artifacts/` and the usual build folders; none matches `packaging/windows/Enigma.Msi.Worker/`
  (checked). `.gitattributes` marks `*.dll` / `*.exe` binary; `*.bat` is CRLF.
- Windows PowerShell 5.1 reads a BOM-less script as ANSI, and `.editorconfig` says UTF-8. So the `.ps1` stays ASCII.
- **Tests:** `PackagingScriptsTests` (Desktop) pins the publish scripts; there is no display-name or assembly-name
  consistency suite here (GitClient's hosts for its pins). `RepositoryRoot.Find()` locates the repository.
- **The run may not run `git clean`** in this repository. The script is verified end to end in a scratch clone.

## PHASE02 — The buildmsi script

**Branch:** `feature/feature-e90d-phase02-buildmsi-script`
**Status:** TODO

### Steps

1. `packaging/windows/buildmsi.ps1`: GitClient's script with Launchpad's constants (ASCII, `Set-StrictMode`,
   `$ErrorActionPreference = 'Stop'`, comment-based help like `publish.ps1`), resolved from its own location:
   1. constants: `$UpgradeCode = 'b4c2d5a2-9182-4c17-b570-c6019eb5ec92'`, `$ProductName = 'Enigma Launchpad'`,
      the manufacturer, `$Assembly = 'Enigma.Launchpad.Desktop'`;
   2. check `git`, `dotnet` and `wix` are on the `PATH`, and the vendored worker exists;
   3. read and check (`^\d+\.\d+\.\d+$`) the version in `Directory.Build.props`;
   4. `git -C <root> clean -dxf`; stop on a non-zero exit code;
   5. run `publish.ps1`; stop on a non-zero exit code; check the exe and `app.ico` are in the publish folder;
   6. write `artifacts/Enigma.Launchpad.X.Y.Z.msipkg.json` (UTF-8 without BOM): `PerMachine`,
      `%ProgramFiles%\Enigma Launchpad`, `compression` `None`, `app.ico` as the Control Panel icon and both
      shortcuts' icon, shortcuts in `%Desktop%` and `%ProgramMenu%` named "Enigma Launchpad" targeting
      `[INSTALLDIR]\Enigma.Launchpad.Desktop.exe`;
   7. run `Enigma.Msi.Worker.exe build <profile>`; exit with its code; on success print the MSI's path and the time.
2. `packaging/windows/buildmsi.bat`: runs `buildmsi.ps1` through `powershell -NoProfile -ExecutionPolicy Bypass
   -File`, and passes its exit code on.
3. `tests/Enigma.Launchpad.Desktop.UnitTests/WindowsInstallerScriptTests.cs`: the three pins (decisions table).
4. Docs: `README.md` (a *Windows installer* section after *Publish*; the layout table's `packaging/windows` row);
   `docs/RELEASE.md` (§6 Windows has an installer; §7 a Windows check; *Why there is no MSI profile* becomes *The
   Windows installer's identity*).
5. Verify in a scratch clone: commit the dev's tree there, run `buildmsi.bat`, then read the MSI's `Property`,
   `Directory`, `Shortcut`, `Upgrade`, `Icon` and `Media` tables. Also check that a missing `wix` stops the script
   before anything is cleaned.

### Acceptance criteria

- In the scratch clone, `buildmsi.bat` exits 0 and leaves `artifacts/Enigma.Launchpad.<version>.msi` and its
  `.msipkg.json`; `git status --porcelain` is empty afterwards.
- The MSI's tables show:
  - `ProductName` "Enigma Launchpad", `Manufacturer` "Josué Clément", `ProductVersion` = the
    `Directory.Build.props` version;
  - `UpgradeCode` `{B4C2D5A2-9182-4C17-B570-C6019EB5EC92}`, `ALLUSERS` 1, `ARPPRODUCTICON` set;
  - `INSTALLDIR` "Enigma Launchpad" under `ProgramFilesFolder`;
  - two "Enigma Launchpad" shortcuts (`DesktopFolder`, `ProgramMenuFolder`) on
    `[INSTALLDIR]\Enigma.Launchpad.Desktop.exe`, each with an icon.
- The profile says `"compression": "None"`.
- A missing `wix` stops the script before `git clean`, with the install command in the message.
- The Release build has zero warnings; the whole suite (with the new tests) shows no new failure.

## Out of scope

- Installing, launching or uninstalling the MSI (outward-facing; the user's).
- Signing the MSI; a 64-bit package (Enigma.Msi has no platform setting).
- Changing Enigma.Msi itself, or the publish (the PDBs it carries).
- Options the user did not ask for (`-NoClean`, …).
