# FEATURE-003B — Icon set that fills the frame

**Status:** DONE
**Type:** FEATURE
**Branch:** `feature/feature-003b-icon-fills-frame`
**Run:** feature/2026-11-04-icons-release

## Objective

Replace the application icon with the new set in `C:\Dev\EnigmaLibs\Branding\Apps\final3\launchpad`
(`enigma-launchpad.ico`, ten PNG frames, one SVG master) everywhere the application and its installers carry it: the
executable, the window and taskbar, the About dialog, the Windows installer (MSI shortcuts and *Installed apps*), the
Linux installer, and the SVG master.

## Context & constraints

- **The new artwork** is FEATURE-BF01's drawing (LP-A2, the rocket in the *Soft* palette, transparent background,
  the window a hole in the body) **scaled by 1.4452 and centred, so it fills the frame**: its longest side spans 16
  to 240 of the 256-unit view box. Generated by `Branding/Apps/export.py final3`, which the SVG's header comment
  names.
- **The new `.ico`** has the same shape as today's: ten 32-bit RGBA PNG frames (16, 20, 24, 32, 40, 48, 64, 96, 128,
  256). Each frame is byte for byte the matching `png/enigma-launchpad-N.png` (checked while planning).
- **Where the icon lives** (unchanged since FEATURE-BF01):
  - `src/Enigma.Launchpad.Desktop/Assets/app.ico`: the `ApplicationIcon` (the executable, so the taskbar),
    `MainWindow.Icon`, and the `app.ico` copied beside the executable;
  - `src/Enigma.Launchpad.Desktop/Assets/app-256.png`: the About dialog's image, the `.ico`'s 256 frame byte for
    byte;
  - `packaging/icon/enigma-launchpad.svg`: the master;
  - `packaging/linux/icons/enigma-launchpad-{16,24,32,48,64,96,128,256}.png`: what `install.sh` installs
    (`ICON_SIZES`).
- **The Windows installer** needs no change of its own: `buildmsi.ps1` takes `app.ico` from the publish folder as the
  MSI's product icon and its two shortcuts' icon.
- `AppIconTests` (Desktop tests) pins the frames, the About copy, the Linux copies and the output copy.
- The source directory is outside the repository and is left in place.

## Steps

1. Copy, byte for byte:
   - `enigma-launchpad.ico` → `src/Enigma.Launchpad.Desktop/Assets/app.ico`;
   - `png/enigma-launchpad-256.png` → `src/Enigma.Launchpad.Desktop/Assets/app-256.png`;
   - `enigma-launchpad.svg` → `packaging/icon/enigma-launchpad.svg`;
   - the 16, 24, 32, 48, 64, 96, 128 and 256 PNGs → `packaging/linux/icons/`.
2. Check that no current prose describes the icon's size within its frame (README, `docs/RELEASE.md`, comments,
   tests). Fix any that does. Past release notes stay as they are.
3. Release build, whole suite.

## Acceptance criteria

- The destinations hold the new files byte for byte (`cmp`; the SVG may differ only in line endings).
- `AppIconTests` pass against the new files.
- The `app.ico` beside the Release executable is the new file.
- The Release build has zero warnings and the whole suite shows no new failure against the run's baseline.

## Out of scope

- The application's accent colours.
- Release notes and version (FEATURE-8698).
- Changing the sizes the Linux installer installs (still eight) or the `.ico`'s frames (still ten).
- Building an MSI (the user runs `buildmsi` after the release).
