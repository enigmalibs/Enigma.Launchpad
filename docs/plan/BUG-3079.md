# BUG-3079 — Unreliable automatic icons

**Status:** DONE
**Type:** BUG
**Branch:** `bugfix/bug-3079-phaseNN-<slug>` (one per phase)
**Run:** vibe/2026-10-13-icons-descriptions-tile-actions

## Objective

Find program and website icons more often. The "lost after a restart" symptom itself is fixed by
FEATURE-3349 PHASE02 (icons found once are kept in `launchpad.json`); this item makes the finding more reliable.

## Context & constraints

- `ShellProgramIconReader` calls `SHCreateItemFromParsingName` + `IShellItemImageFactory.GetImage`
  (`SIIGBF_ICONONLY`, 48 px) on whatever thread `ProgramIcons` runs it — thread-pool (MTA) threads, many in
  parallel at start-up. Shell icon handlers are apartment-sensitive and some fail outside an STA.
- An image whose alpha is zero everywhere is answered `null`: legacy icons without an alpha channel come out that
  way, and their tile keeps the glyph although the icon exists.
- `WebsiteIconFetcher` tries up to three `<link>` icons, then `/favicon.ico`; SVG is skipped. Many sites declare
  their raster icons only in a web-app manifest (`<link rel="manifest">`). The page is requested with
  `Accept: text/html` only.
- Nothing here may widen what is requested of a site: only its root page and icon URLs (and now its manifest).

## Design

### Program icons (PHASE01)

- Every shell read runs on a dedicated **STA thread** of its own, the caller blocked until it ends (the reader is
  already documented as blocking and is always called off the UI thread).
- When `GetImage` fails or gives no alpha, fall back to `SHGetFileInfo(SHGFI_ICON | SHGFI_LARGEICON)`: the icon's
  colour bitmap, with alpha taken from its mask when the colour bitmap carries none (`GetIconInfo`); every handle
  released. Still nothing → `null`.
- Pure helpers (`HasAlpha`, applying a mask) are internal and unit-tested.

### Website icons (PHASE02)

- `FaviconLinks` also reports the page's manifest link; the fetcher reads the manifest (≤ 64 KB, JSON, http/https,
  bounded by the same timeouts) and adds its `icons` (`src`, `sizes`, `type`; SVG skipped; `sizes: any` counted as
  unsized) to the candidates, ranked with the page's links by the existing size rule; still at most three, then
  `/favicon.ico`. A manifest that is missing or malformed is ignored.
- The page request sends a browser-like `Accept` (`text/html,application/xhtml+xml;q=0.9,*/*;q=0.8`).

## Phases

### PHASE01 — Program icon reading

**Status:** DONE

Steps:
1. STA runner inside `ShellProgramIconReader` (Windows only).
2. `SHGetFileInfo` fallback with mask-derived alpha.
3. Tests: helpers (alpha detection, mask application); on Windows: a program read from a thread-pool thread still
   gives its icon, the read runs on an STA thread, the fallback alone gives a program's icon, a missing program
   gives none.

Acceptance criteria:
- Shell reads run on STA threads; an icon without alpha is shown instead of the glyph.
- 0 warnings; suite green.

### PHASE02 — Website icon finding

**Status:** DONE

Steps:
1. `FaviconLinks`: manifest link; manifest icon parsing and ranking.
2. `WebsiteIconFetcher`: manifest request, merged candidates, `Accept` header.
3. Tests: manifest link found; manifest icons parsed (relative `src`, sizes, `any`, SVG skipped, non-http dropped,
   malformed JSON ignored); the fetcher uses a manifest icon when the page links none, keeps the request bound, and
   sends the new `Accept`.

Acceptance criteria:
- A site whose only raster icon is in its manifest gets that icon.
- At most 1 page + 1 manifest + 4 icon requests per site.
- 0 warnings; suite green.

## Out of scope

- SVG rendering; third-party favicon services; trying a parent domain; credentials for intranet sites.
- Linux and macOS program icons.
